## החלטה מרכזית

להפוך את המערכת מ"אוסף מסכי אדמין" ל**מרכז שליטה תפעולי יומי**.

- פחות כרטיסים דקורטיביים, פחות עומס ויזואלי, היררכיה ברורה יותר
- כל מסך חייב לענות מיד על שלוש שאלות:
  1. מה קורה עכשיו?
  2. מה דורש טיפול?
  3. מה הפעולה הבאה?

**החלטת ישיבה:** לא מוסיפים פיצ'רים עסקיים חדשים כרגע. קודם מאחדים מראה, תחושה והתנהגות למוצר אחד — רגוע, ברור, מהיר ומקצועי.

---

## עקרונות רוחביים

1. **דשבורד = מסך עבודה**, לא מסך סטטיסטיקות.
2. **צבעים הם שפה תפעולית** (מיפוי לטוקני אותות ב־`globals.css`):
   - כחול → פעולה ומידע (`--signal-progress`)
   - פעולה ראשית → tenant burgundy
   - כתום → דורש תשומת לב (`--signal-warning`)
   - אדום → חריג או דחוף (`--signal-critical`) — רק לאזהרות הרסניות
   - ירוק → הושלם / תקין (`--signal-resolved`)
3. **מבנה אחיד:** כותרת → תיאור קצר → פעולה ראשית → חיפוש/סינון → תוכן.
4. **מובייל קודם:** ללא גלילה אופקית; ללא פאנלים קבועים שמכסים תוכן.
5. **מצבי מערכת מלאים:** טעינה, אין נתונים, שגיאה, הרשאות חסרות, הצלחה אחרי פעולה.
6. **אחידות רכיבים:** תגיות, טבלאות, פילטרים, Dialogs, כפתורים, טפסים.

### מה להסיר

- כרטיסים קטנים ללא פעולה
- מספרים שלא מובילים למסך המשך
- עומס גרפים כשאין החלטה שנגזרת מהם
- שטחים כהים גדולים שמכבידים על המסך
